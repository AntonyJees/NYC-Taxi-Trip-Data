# Phase 2 hand-in

The brief requests a 200-word explanation pasted into the PebblePad field and a TXT containing a real GitHub repository link. The ZIP is a convenient development package requested by the student; it does not replace those two formal submissions.

1. Extract the ZIP and read README.md.
2. Run the pipeline locally with Docker Desktop or Docker Engine and Compose v2. Save its console output and Docker status as your own deployment evidence. This package distinguishes supplied application tests from Docker runtime verification.
3. Create an empty repository in your GitHub account. Do not initialise it with a README if using the included bundle.
4. Restore history using the bundle, then run the publishing script as described in README.md. Your Git credential manager handles sign-in.
5. Open the actual repository URL and check that the code is visible to your assessor. Confirm that .env, raw data and credentials are absent.
6. After a successful push, submission/Repository_Link.txt contains the actual URL and the explanation contains that same URL. No real GitHub URL is claimed before this step.
7. Paste the explanation into PebblePad, then upload the link TXT. Replace the submission filename with your surname, first name and matriculation number, following the brief: Surname-FirstName_MatriculationNumber_Data-Engineering_P2_S.txt. Those personal details were not supplied and have not been invented.
8. Keep the modified Phase 1 DOCX and the separate Phase 1 architecture PNG. The 200-word Phase 1 concept is supplied separately if that field also needs correction.

The modified Phase 1 DOCX retains its original formatting and embedded conceptual figure. Its references now point to directly relevant primary technical sources; unsupported and unrelated references were removed. A change note explains the revision.
